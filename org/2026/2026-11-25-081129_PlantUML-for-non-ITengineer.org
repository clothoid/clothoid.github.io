#+LANGUAGE: ja
#+OPTIONS: toc:nil num:nil author:nil date:nil

* はじめに

仕事や日常生活の中で、次のようなことを感じた経験はないでしょうか。

- 文章だけでは、作業の流れがうまく伝わらない
- 複数の人の役割や関係を整理したい
- 会議で出たアイデアを分かりやすくまとめたい
- PowerPointで図を作るのに時間がかかる
- 図を修正するたびに、矢印や図形の位置を調整するのが面倒

このような場面で役に立つツールの一つが、*PlantUML（プラントユーエムエル）* です。

PlantUMLはソフトウェア開発でよく使われるツールですが、用途はそれだけではありません。業務の整理、情報共有、旅行の計画、イベントの準備などにも活用できます。

この記事では、プログラミングやシステム設計の知識がない方を対象に、PlantUMLの基本を紹介します。

* 1. PlantUMLとは何か

PlantUMLは、テキストから図を生成するツールです。

一般的な作図ツールでは、四角形や矢印を配置し、その中に文字を入力して図を作ります。

PlantUMLでは、代わりに次のようなテキストを書きます。

#+begin_src text
@startuml
客 -> 店員 : 注文する
店員 -> 客 : 料理を渡す
@enduml
#+end_src

すると、以下のような図が生成されます。

#+begin_src plantuml
@startuml
客 -> 店員 : 注文する
店員 -> 客 : 料理を渡す
@enduml
#+end_src

四角形や矢印の配置は、PlantUMLが自動的に行います。

内容を変更したい場合は、元のテキストを書き換えるだけです。

このように、図形を直接操作するのではなく、図にしたい内容をテキストで記述するのがPlantUMLの特徴です。

** PlantUMLを使うメリット

- 図形や矢印の位置を手作業で調整する必要が少ない
- テキストを書き換えるだけで図を修正できる
- テキストとして保存・共有できる
- 変更前と変更後の違いを確認しやすい
- ChatGPTなどの生成AIと組み合わせやすい

特に、何度も修正する可能性がある図や、複数の人で内容を確認する図に適しています。

* 2. UMLとは何か

PlantUMLという名前には「UML」という言葉が含まれています。

UMLは、Unified Modeling Language（統一モデリング言語）の略称です。

物事の構造や振る舞いを図で表現するための、標準化された表記方法です。

もともとはソフトウェアの設計などを目的としていますが、その考え方は身近な物事の整理にも応用できます。

例えば、レストランについて説明するときにも、さまざまな視点があります。

- 料理はどのような手順で提供されるのか
- 客と店員はどのようなやり取りをするのか
- 注文はどのような状態にあるのか
- 客、注文、料理にはどのような関係があるのか

これらを一つの図ですべて表現する必要はありません。

*何を伝えたいかによって、図の種類を使い分けます。*

PlantUMLでは、UMLで定義された図に加えて、マインドマップやガントチャートなども作成できます。

なお、この記事は厳密なUMLの仕様を学ぶためのものではありません。まずは、図の種類によって何を表現できるのかを理解することを目的としています。

* 3. まずは使ってみる

PlantUMLを試すために、特別なソフトウェアをインストールする必要はありません。

以下の公式オンラインエディターを利用できます。

- [[https://editor.plantuml.com/][PlantUML公式オンラインエディター]]

この記事に掲載されているサンプルコードをコピーし、エディターの入力欄に貼り付けてみてください。

テキストが図に変換されます。

まずは難しいルールを覚えず、サンプルの日本語を書き換えてみるだけで十分です。

例えば、最初に紹介したレストランの例を、宅配便の受け取りに変更してみましょう。

#+begin_src text
@startuml
配達員 -> 受取人 : 荷物を渡す
受取人 -> 配達員 : 受け取りを確認する
@enduml
#+end_src

#+begin_src plantuml
@startuml
配達員 -> 受取人 : 荷物を渡す
受取人 -> 配達員 : 受け取りを確認する
@enduml
#+end_src

このように、テキストを書き換えるだけで、別の内容を表現する図を作成できます。

* 4. 作業の流れを表現する ― アクティビティ図

アクティビティ図は、「何を、どのような順番で行うのか」を表現する図です。

一般的なフローチャートに近いものです。

** 基本的な作業の流れ

例えば、朝のコーヒーを用意する手順を考えてみましょう。

#+begin_src text
@startuml
start
:お湯を沸かす;
:コーヒーを抽出する;
:カップに注ぐ;
stop
@enduml
#+end_src

#+begin_src plantuml
@startuml
start
:お湯を沸かす;
:コーヒーを抽出する;
:カップに注ぐ;
stop
@enduml
#+end_src

基本的な書き方は次のとおりです。

| 記述         | 意味       |
|--------------+------------|
| =start=      | 作業の開始 |
| =:作業内容;= | 一つの作業 |
| =stop=       | 作業の終了 |

上から下に向かって、作業が進んでいきます。

** 条件によって作業を分ける

条件によって、異なる作業を行う場合も表現できます。

例えば、外出するときに傘を持っていくかどうかを判断する場面です。

#+begin_src text
@startuml
start
if (雨が降っている？) then (はい)
  :傘を持つ;
else (いいえ)
  :傘を持たない;
endif
:出かける;
stop
@enduml
#+end_src

#+begin_src plantuml
@startuml
start
if (雨が降っている？) then (はい)
  :傘を持つ;
else (いいえ)
  :傘を持たない;
endif
:出かける;
stop
@enduml
#+end_src

条件によって矢印が枝分かれすることで、判断とその結果を表現できます。

** 仕事での活用例

- 経費精算の手順
- 申請・承認の流れ
- 問い合わせ対応
- 商品の発送手順
- 新入社員の受け入れ手順
- 作業マニュアルの作成

業務の手順を整理したい場合には、まずアクティビティ図を検討するとよいでしょう。

* 5. 人と人のやり取りを表現する ― シーケンス図

シーケンス図は、「誰が、誰に、何を、どのような順番で伝えるのか」を表現する図です。

** レストランでの注文

例えば、レストランで料理を注文する場面を考えてみましょう。

#+begin_src text
@startuml
actor "客" as Customer
participant "店員" as Staff
participant "調理担当" as Cook

Customer -> Staff : 料理を注文する
Staff -> Cook : 注文を伝える
Cook -> Staff : 料理を渡す
Staff -> Customer : 料理を提供する
@enduml
#+end_src

#+begin_src plantuml
@startuml
actor "客" as Customer
participant "店員" as Staff
participant "調理担当" as Cook

Customer -> Staff : 料理を注文する
Staff -> Cook : 注文を伝える
Cook -> Staff : 料理を渡す
Staff -> Customer : 料理を提供する
@enduml
#+end_src

図の上部には、やり取りに参加する人が並んでいます。

図の上から下へ向かって、時間が進みます。

矢印は、誰から誰へのやり取りなのかを表しています。

例えば、次の一行は「客が店員に料理を注文する」という意味です。

#+begin_src text
Customer -> Staff : 料理を注文する
#+end_src

=Customer= や =Staff= は、登場人物をコードの中で識別するための名前です。

=actor= や =participant= を使って、登場人物を定義しています。

** アクティビティ図との違い

アクティビティ図とシーケンス図は、どちらも物事の流れを表現できます。

ただし、注目している対象が異なります。

| 図                 | 注目すること             |
|--------------------+--------------------------|
| アクティビティ図   | どのような作業を行うか   |
| シーケンス図       | 誰と誰がやり取りするか   |

例えば、料理の作り方を説明するならアクティビティ図が適しています。

客、店員、調理担当の連携を説明するなら、シーケンス図が適しています。

** 仕事での活用例

- 顧客と営業担当者のやり取り
- 部署間の情報共有
- 書類の受け渡し
- 問い合わせへの対応
- 取引先との受発注
- 会議前後の連絡手順

複数の関係者が登場する業務を整理する際に便利です。

* 6. モノや情報の関係を表現する ― クラス図

クラス図は、「どのような種類のモノや情報があり、それらがどのような関係にあるのか」を表現する図です。

「クラス」という言葉は聞き慣れないかもしれませんが、ここでは、共通する特徴を持つモノや情報の種類と考えてください。

** 図書館の情報を整理する

例えば、図書館では次のような情報を管理しています。

- 利用者：氏名、利用者番号
- 本：書名、著者
- 貸出記録：貸出日、返却期限

これらを図にしてみましょう。

#+begin_src text
@startuml
hide circle
hide empty methods

class "利用者" as User {
  氏名
  利用者番号
}

class "本" as Book {
  書名
  著者
}

class "貸出記録" as Loan {
  貸出日
  返却期限
}

User -- Loan
Loan -- Book
@enduml
#+end_src

#+begin_src plantuml
@startuml
hide circle
hide empty methods

class "利用者" as User {
  氏名
  利用者番号
}

class "本" as Book {
  書名
  著者
}

class "貸出記録" as Loan {
  貸出日
  返却期限
}

User -- Loan
Loan -- Book
@enduml
#+end_src

四角形はモノや情報の種類を表し、その中には、それぞれが持つ情報を書いています。

線は、それらの関係を表しています。

なお、ここでいう「本」は特定の一冊ではなく、本という種類を指しています。

クラス図には本来、より細かな表記ルールがありますが、最初は次の三つを考えるだけで十分です。

- どのような種類のモノや情報があるか
- それぞれにどのような特徴があるか
- それぞれがどのように関係しているか

** 仕事での活用例

- 顧客情報と契約情報の関係
- 商品と注文の関係
- 社員と所属部署の関係
- 研修と受講者の関係
- 予算と費用の関係

情報の種類や関係を整理するときに活用できます。

* 7. 状態の変化を表現する ― 状態遷移図

状態遷移図は、「ある対象が、どのようなきっかけで別の状態になるのか」を表現する図です。

** ネット通販の注文状況

例えば、ネット通販で商品を注文した後の状況を考えてみましょう。

注文には、次のような状態があります。

- 注文済み
- 発送済み
- 配達完了
- キャンセル済み

これらの状態が、どのように変化するのかを図にします。

#+begin_src text
@startuml
state "注文済み" as Ordered
state "発送済み" as Shipped
state "配達完了" as Delivered
state "キャンセル済み" as Cancelled

[*] --> Ordered
Ordered --> Shipped : 商品を発送
Shipped --> Delivered : 商品を配達
Ordered --> Cancelled : 注文を取り消す
Delivered --> [*]
Cancelled --> [*]
@enduml
#+end_src

#+begin_src plantuml
@startuml
state "注文済み" as Ordered
state "発送済み" as Shipped
state "配達完了" as Delivered
state "キャンセル済み" as Cancelled

[*] --> Ordered
Ordered --> Shipped : 商品を発送
Shipped --> Delivered : 商品を配達
Ordered --> Cancelled : 注文を取り消す
Delivered --> [*]
Cancelled --> [*]
@enduml
#+end_src

四角形は現在の状態を表し、矢印は状態が変化することを表しています。

矢印に添えられた文字は、状態が変化するきっかけを表しています。

** アクティビティ図との違い

アクティビティ図は「何をするか」に注目します。

状態遷移図は「今、どのような状態にあるか」に注目します。

例えば、次のように区別できます。

| 作業         | 状態       |
|--------------+------------|
| 注文する     | 注文済み   |
| 商品を発送する | 発送済み |
| 商品を配達する | 配達完了 |
| 注文を取り消す | キャンセル済み |

動作と状態の違いを意識すると、図を使い分けやすくなります。

** 仕事での活用例

- 商談の進捗状況
- 契約の締結状況
- 問い合わせの対応状況
- 申請書の承認状況
- タスクの進捗管理
- 商品の在庫状況

業務の中で管理する対象が、どのような状態を取り得るのかを整理する際に便利です。

* 8. アイデアを整理する ― マインドマップ

マインドマップは、一つのテーマから関連する情報を枝分かれさせて整理する図です。

マインドマップはUMLの一種ではありませんが、PlantUMLで作成できます。

** 旅行の準備

例えば、旅行の準備について考えてみましょう。

#+begin_src text
@startmindmap
* 旅行の準備
** 交通
*** 新幹線
*** レンタカー
** 宿泊
*** ホテル
*** 旅館
** 観光
*** 観光地
*** レストラン
** 持ち物
*** 衣類
*** 充電器
@endmindmap
#+end_src

#+begin_src plantuml
@startmindmap
* 旅行の準備
** 交通
*** 新幹線
*** レンタカー
** 宿泊
*** ホテル
*** 旅館
** 観光
*** 観光地
*** レストラン
** 持ち物
*** 衣類
*** 充電器
@endmindmap
#+end_src

アスタリスクの数によって、情報の階層を表現しています。

- =*= ：中心となるテーマ
- =**= ：テーマに関連する項目
- =***= ：さらに細分化された項目

複雑な記法を覚えなくても、情報を階層的に整理できます。

** 仕事での活用例

- 会議の論点整理
- アイデア出し
- 課題の分類
- プレゼンテーションの構成
- 勉強した内容の整理
- 新しい企画の検討

情報を集めて分類したいときには、マインドマップが便利です。

* 9. 誰が何をできるかを表現する ― ユースケース図

ユースケース図は、「誰が、どのようなことをできるのか」を表現する図です。

** スポーツジムの利用

例えば、スポーツジムには利用者とスタッフがいます。

利用者はトレーニングやレッスンへの参加ができます。

スタッフは入会手続きや施設の管理を行います。

#+begin_src text
@startuml
left to right direction

actor "利用者" as Member
actor "スタッフ" as Staff

rectangle "スポーツジム" {
  usecase "トレーニングする" as Training
  usecase "レッスンに参加する" as Lesson
  usecase "入会手続きを行う" as Registration
  usecase "施設を管理する" as Management
}

Member -- Training
Member -- Lesson
Staff -- Registration
Staff -- Management
@enduml
#+end_src

#+begin_src plantuml
@startuml
left to right direction

actor "利用者" as Member
actor "スタッフ" as Staff

rectangle "スポーツジム" {
  usecase "トレーニングする" as Training
  usecase "レッスンに参加する" as Lesson
  usecase "入会手続きを行う" as Registration
  usecase "施設を管理する" as Management
}

Member -- Training
Member -- Lesson
Staff -- Registration
Staff -- Management
@enduml
#+end_src

人型の記号は、サービスや活動に関わる役割を表しています。

楕円形は、その役割が関わる活動や機能を表しています。

シーケンス図とは異なり、やり取りの順序は表現していません。

** 仕事での活用例

- サービスの利用者と提供機能の整理
- 部署ごとの役割の整理
- 社内制度の利用方法
- 新しいサービスの検討
- 業務に関わる関係者の整理

誰が何をするのか、誰がどのようなサービスを利用するのかを大まかに把握する際に便利です。

* 10. スケジュールを表現する ― ガントチャート

ガントチャートは、作業の期間や開始・終了時期を横棒で表現する図です。

ガントチャートもUMLの一種ではありませんが、PlantUMLで作成できます。

** イベントの準備

例えば、イベントを開催するために、次のような準備が必要だとします。

- 会場の手配
- 参加者の募集
- 資料の作成
- 当日の準備

#+begin_src text
@startgantt
Project starts 2027-01-04

[会場の手配] lasts 3 days
[参加者の募集] lasts 10 days
[参加者の募集] starts at [会場の手配]'s end
[資料の作成] lasts 7 days
[資料の作成] starts at [会場の手配]'s end
[当日の準備] lasts 2 days
[当日の準備] starts at [参加者の募集]'s end
@endgantt
#+end_src

#+begin_src plantuml
@startgantt
Project starts 2027-01-04

[会場の手配] lasts 3 days
[参加者の募集] lasts 10 days
[参加者の募集] starts at [会場の手配]'s end
[資料の作成] lasts 7 days
[資料の作成] starts at [会場の手配]'s end
[当日の準備] lasts 2 days
[当日の準備] starts at [参加者の募集]'s end
@endgantt
#+end_src

それぞれの横棒が、作業を行う期間を表しています。

作業の期間や、ほかの作業との前後関係を整理できます。

** 仕事での活用例

- プロジェクトの進捗管理
- イベントの開催準備
- 新サービスの提供開始に向けた準備
- 年間計画の作成
- 研修の実施計画

複数の作業を並行して進める場合や、作業の前後関係を確認する場合に便利です。

* 11. どの図を使えばよいのか

ここまで紹介した図を整理してみましょう。

| 表現したいこと           | 図の種類           |
|--------------------------+--------------------|
| 作業の手順や流れ         | アクティビティ図   |
| 人や組織のやり取り       | シーケンス図       |
| モノや情報の構造・関係   | クラス図           |
| 状態の変化               | 状態遷移図         |
| アイデアや情報の階層     | マインドマップ     |
| 誰が何をできるか         | ユースケース図     |
| 作業の期間やスケジュール | ガントチャート     |

大切なのは、図の名前を暗記することではありません。

*自分が何を整理したいのか、相手に何を伝えたいのかを考えることです。*

同じ題材であっても、目的が異なれば適した図は変わります。

例えば、レストランについて説明する場合でも、次のように使い分けることができます。

| 説明したいこと           | 図の種類           |
|--------------------------+--------------------|
| 料理の作り方             | アクティビティ図   |
| 客と店員のやり取り       | シーケンス図       |
| 客・注文・料理の関係     | クラス図           |
| 注文の進捗状況           | 状態遷移図         |
| 新しいメニューの案       | マインドマップ     |
| 客や店員ができること     | ユースケース図     |
| 新店舗の開店スケジュール | ガントチャート     |

複数の図を組み合わせることで、物事を異なる視点から理解することもできます。

* 12. 生成AIと組み合わせて使う

PlantUMLはテキストで記述するため、ChatGPTやClaude、Microsoft Copilotなどの生成AIと組み合わせて使うこともできます。

** 文章から図を作成する

例えば、生成AIに次のように依頼してみましょう。

#+begin_src text
以下の業務を分かりやすい図にしてください。

目的に合った図の種類を選び、
PlantUML形式でコードを出力してください。

図の中の文字は日本語にしてください。
元の文章にない情報は追加しないでください。

業務内容：
社員が経費精算を申請します。
上司が申請内容を確認します。
問題があれば社員に差し戻します。
問題がなければ承認し、経理部門に送ります。
経理部門が支払いを行います。
#+end_src

生成AIは、文章の内容に応じたPlantUMLのコードを生成できます。

例えば、次のようなコードです。

#+begin_src text
@startuml
|社員|
start
:経費精算を申請する;

|上司|
:申請内容を確認する;

if (問題がある？) then (はい)
  :社員に差し戻す;
  |社員|
  :差し戻しを受け取る;
  stop
else (いいえ)
  |上司|
  :申請を承認する;
  :経理部門に送る;
  |経理部門|
  :支払いを行う;
  stop
endif
@enduml
#+end_src

#+begin_src plantuml
@startuml
|社員|
start
:経費精算を申請する;

|上司|
:申請内容を確認する;

if (問題がある？) then (はい)
  :社員に差し戻す;
  |社員|
  :差し戻しを受け取る;
  stop
else (いいえ)
  |上司|
  :申請を承認する;
  :経理部門に送る;
  |経理部門|
  :支払いを行う;
  stop
endif
@enduml
#+end_src

この図は、担当者ごとに領域を分けたアクティビティ図です。

担当者ごとに作業領域を分ける表現を、スイムレーンと呼びます。

誰がどの作業を担当するのかを分かりやすく表現できます。

なお、元の文章には差し戻し後の再申請について記載されていないため、この例では再申請の流れを描いていません。

** 生成AIに修正を依頼する

生成された図を見て、さらに修正を依頼することもできます。

#+begin_src text
もう少しシンプルな図にしてください。

担当者ごとに作業を分けてください。

図を横向きにしてください。

専門用語を減らしてください。

同じ業務をシーケンス図でも表現してください。
#+end_src

PlantUMLの書き方をすべて覚えなくても、自然な日本語で指示しながら図を作成できます。

** 図から文章を作成する

反対に、PlantUMLのコードを生成AIに渡して、文章で説明してもらうこともできます。

#+begin_src text
以下のPlantUMLの内容を、
業務を知らない人にも分かるように説明してください。

また、業務の流れに不明確な点や、
確認が必要な点があれば指摘してください。
#+end_src

業務の引き継ぎや、作業マニュアルの作成にも活用できる可能性があります。

** 生成AIを利用する際の注意点

生成AIが作成した図が正しいとは限りません。

次のような点を確認してください。

- 元の文章にない内容が追加されていないか
- 必要な情報が省略されていないか
- 実際の業務の流れと合っているか
- 関係者の役割が正しく表現されているか
- 矢印の向きや前後関係が正しいか

また、生成AIや外部のオンラインエディターを利用する場合には、会社の機密情報や個人情報の取り扱いに注意してください。

所属組織の情報管理ルールに従って利用する必要があります。

* 13. PowerPointやExcelとは何が違うのか

PlantUMLは、PowerPointやExcelの代わりになる万能ツールではありません。

それぞれに得意なことがあります。

| 観点           | PlantUML                 | PowerPointなど           |
|----------------+--------------------------+--------------------------|
| 図の作成       | テキストを書く           | 図形を配置する           |
| レイアウト     | 主に自動                 | 主に手動                 |
| 内容の修正     | テキストを編集する       | 図形や文字を編集する     |
| デザイン自由度 | 比較的低い               | 高い                     |
| 変更履歴の比較 | テキストとして比較可能   | 利用する機能による       |
| 生成AIとの連携 | テキストとして扱いやすい | 利用する機能による       |

業務フローや関係図など、内容の正確さや修正のしやすさを重視する場合には、PlantUMLが便利です。

一方で、細かなデザインや見栄えを重視するプレゼンテーション資料では、PowerPointの方が適している場合もあります。

PlantUMLで作成した図をPNGやSVGなどの画像に変換し、PowerPointの資料に貼り付けるという使い方もできます。

どちらか一方に統一するのではなく、用途に応じて使い分けることが重要です。

* 14. まとめ

PlantUMLは、テキストから図を生成するツールです。

システム開発だけでなく、業務の整理、情報共有、アイデアの可視化などにも活用できます。

最初から難しい記法を覚える必要はありません。

まずは、次のような順番で使ってみることをおすすめします。

1. 身近な作業をアクティビティ図にしてみる
2. 人と人のやり取りをシーケンス図にしてみる
3. アイデアをマインドマップにしてみる
4. 自分の仕事に関する内容を図にしてみる
5. 生成AIを使って図を作成・修正してみる

図を描くこと自体が目的ではありません。

*図を使うことで、物事を理解しやすくし、他の人と認識を共有しやすくすることが目的です。*

PlantUMLは、そのための手段の一つです。

まずは身近な題材から、気軽に試してみてください。
